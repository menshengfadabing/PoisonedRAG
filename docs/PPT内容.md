## 课题介绍

基于检索增强的大模型对话系统安全防护设计与实现

检索增强生成（RAG）技术通过引入外部知识，有效提升了大模型对话系统的事实准确性与可验证性，已成为主流应用方向。但检索语料的外部来源特性，使其易遭受数据投毒等安全攻击，进而导致生成内容出现知识错误、恶意引导等问题，严重影响系统可信度与使用安全性。本课题以"检索增强对话系统的投毒风险防护"为核心，任务是搭建轻量化 RAG 对话框架，设计检索语料的基础过滤机制与生成结果的安全校验规则，通过构建小型模拟投毒语料库开展防护效果测试，实现对污染数据的有效拦截与风险内容的合理处置，最终完成兼具事实响应能力与基础安全防护功能的对话系统开发。该方法通过"语料过滤—生成校验—效果测试"的轻量化技术路径，在保障系统核心使用性能的前提下，有效降低投毒攻击带来的负面影响，兼顾技术落地性与安全实用性。

## 技术选型

| 模块 | 技术方案 | 选型理由 |
|------|---------|---------|
| **对话框架** | LangGraph + LangChain | 成熟的 RAG 编排生态，支持流式输出与灵活定制 |
| **对话模型** | DeepSeek API | 国产大模型，中文能力强，API 稳定 |
| **嵌入模型** | OpenAI 兼容接口 | 支持 DashScope / Ollama / vLLM 自由切换 |
| **向量数据库** | ChromaDB | 轻量级，支持本地持久化，无需额外部署 |
| **前端界面** | Streamlit | 快速构建交互式 Web 应用，适合原型展示 |
| **文档解析** | pypdf / python-docx / python-pptx | 支持 PDF / Word / PPT 等多格式语料上传 |

**整体架构：** 后端纯 Python 实现，无额外服务依赖，部署门槛低，适合中小规模场景。

## 课题难点

### 难点一：投毒语料的隐蔽性强
- 真实投毒不是明显的恶意代码，而是**混合正常信息的误导建议、错误事实注入**
- 短文本规则匹配容易识别，但长文档中隐藏的恶意内容难以检测
- 攻击手段跨领域：编程、金融、医疗、教育等

### 难点二：防护性能与准确率的平衡
- 过于严格的过滤会导致正常语料被误杀，影响对话质量
- 过于宽松则无法有效拦截投毒攻击
- LLM 审查准确率高但**调用成本高、延迟大**

### 难点三：系统可用性与安全性兼顾
- 需要提供灵活的配置方式，允许用户按需调整防护强度
- 上传、审查、入库的完整流程需要**进度可视化**，避免用户等待焦虑
- 多格式文档解析、文本分割、向量化入库需要稳定可靠的工程实现

## 解决方案

### 三阶段防护机制

```
入库审查（核心防线）  →  检索过滤（可选防线）  →  生成校验（最后防线）
```

**1. 入库审查 — LLM 批量安全审查**
- 规则引擎预筛选：typosquatting 包名检测、敏感关键词匹配、可疑 URL 识别（零 API 调用）
- LLM 批量审查：利用 128K 上下文窗口，**每批 20-100 条语料一次送审**，返回 p/r/f 三档评级
  - **pass**（<0.3）→ 自动入库
  - **review**（0.3-0.7）→ 进入人工审核队列
  - **fail**（≥0.7）→ 拒绝入库

**2. 检索过滤 — 关键词 + 语义异常检测**
- 敏感关键词正则匹配
- 嵌入模型计算与已知恶意模式的语义相似度
- 来源可信度检查（已审查文档标记 `reviewed=True`，仅轻量检查）

**3. 生成校验 — 安全规则 + 事实一致性**
- 正则检测：密码泄露、危险命令、钓鱼链接等
- 语义一致性：校验生成响应与检索文档的事实匹配度
- 置信度评分：多维因子综合评定（安全状态 × 一致性 × 文档数量）

### 投毒语料库构建
- 覆盖 **380+ 条样本**，跨越 **7 大领域**（编程/金融/医疗/教育/法律/日常生活/网络安全）
- 包含 9 种投毒类型：误导建议、事实注入、恶意代码、依赖投毒、后门代码、敏感信息泄露、钓鱼欺诈、错误信息、恶意引导
- 样本从"短而明显"优化为"长而隐蔽"（平均 170+ 字符，混合正常信息与隐藏恶意内容）

### 工程实现优化
- **流式审查 + 进度展示**：每完成一批 LLM 审查即更新进度，支持切换页面不丢失
- **批量向量化**：20 条一组调用 Embedding API，速度提升 7 倍
- **多格式语料上传**：支持 PDF / Word / PPT / Markdown / JSON / TXT
- **一键切换 Embedding 服务**：DashScope / Ollama 本地 / vLLM，前端按钮切换
- **配置持久化**：设置界面修改后实时写入 `.env`，无需重启
